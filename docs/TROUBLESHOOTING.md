# 常见问题

先区分音箱采音、局域网连接和小智账号三个层面。容器正常运行不代表音箱有增强音频，配对成功也不代表实时开关已经打开。

## 安装脚本拒绝继续

- 型号或固件不匹配：本包以 OH2P 1.62.2 为已确认环境，不跳过校验。
- 找不到 `libvpm.so`：使用设备原有固件库，本仓库不提供替代下载。
- ALSA 配置块不符合预期：先确认实际生效配置文件；不要凭习惯填写路径，也不要直接覆盖整份配置。
- 发现已有本项目进程：先按原项目的停止/回退流程退出，确认 owner、client 和其底层录音都已停止，再安装。不要使用 `killall arecord` 等全局命令处理。

启动时发现 PCM3 占用，应先核对路由。若本次安装刚调整 ALSA，需要重启音箱让原生采音按新路由打开声卡；不要手动杀原生语音进程或硬开第二个 owner。

## 不能绑定小智

先确认容器能访问小智服务，音箱能连接 Docker 暴露的端口。使用自己的账号获取当次设备绑定码，过期后重新获取。不要使用他人日志或配置中的验证码。

绑定码没有播报时，可在自己机器查看 `docker compose logs --tail=100 server` 和 `data/config.py` 中的 `VERIFICATION_CODE`。这些内容可能包含身份或对话信息，不要原样发到公开 issue。成功绑定后保留 `data/config.py`，不要每次启动都用样例覆盖它。

## 唤醒没有反应

先看配置里的唤醒词是否与自己说的一致；公开样例是“你好小智”。修改配置后重启服务，让关键词重新生成。

再检查音箱到 Docker 的连接，以及 owner → reader → client 的增强音频链路。曾遇到过“底层 arecord 仍在采音，TCP 仍在线，但 VPM 不再输出增强回调”的故障，所以仅看进程、网络或容器存活不够。

当前 owner 遇到原始输入持续而增强回调停顿 5 秒时会尝试恢复，日志可出现 `enhanced_stream_stalled`。没有该记录只说明保留的日志中未出现，不等于从未断流。恢复仍不成功时，先保存有限的版本与数字状态，再按本项目的停止/启动流程处理；不要额外开一路原始采音来绕过 AEC。

## 能说话，但播报时不能插话

检查 `.env` 中 `OH2P_REALTIME`、`OH2P_AEC_READY`、`OH2P_CANCEL_READY` 是否都为默认的 `1`，更改后是否重建了容器。

确认使用本仓库构建的服务镜像和支持播放取消的客户端。正常 `tts.stop` 只是云端发送完成，不证明插话成功；必须实际在播报时说话，观察播放停止和新语音上行。

若门禁和 RPC 都正常，再检查现场 AEC 信号。插话依赖 VAD 对约 250 毫秒持续语音的判断，电视声、距离、音量与回声都可能影响表现，不能用降低阈值替代排查。

## 没有开始或结束提示音

开始音只在会话准备好后请求；结束音只在实际退出时请求，普通回复结束和插话不会响。确认已启用实时模式，设备固件仍有对应提示音文件和 `qplayer` 接口。

提示音失败不会阻止对话。日志里的 `cue requested` 表示发起播放调用，不等于人耳确认已经听到。

## 配置不生效或身份反复变化

检查 Compose 是否把 `data/config.py` 挂载到 `/app/config.py`，并允许应用写入。该文件既是配置，也承载上游首次连接生成的设备身份和绑定状态。不要把它挂成只读，不要每次重建时重新初始化。

普通唤醒设置和实时适配器不完全相同。当前实时适配器使用 20 秒静默退出；仅修改普通 `wakeup.timeout` 不能作为实时超时已改变的证据。

## 反馈问题时提供什么

提供设备型号与固件、代码版本、容器构建结果、三个开关的值、故障发生在哪一步，以及删去身份信息后的少量错误行即可。不要上传完整配置、绑定码、访问令牌、录音、私有地址或完整对话日志。
