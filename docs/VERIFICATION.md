## 先检查配套边端

1. 确认设备型号与固件版本，确认安装脚本未报告声卡或固件库不匹配。
2. 确认本项目只有一个 owner 和一路底层采音，reader 能持续得到增强 PCM。不要只看进程存在。
3. 确认设备播放取消 RPC 能收到成功响应，客户端播放器可以停止并重新开始。
4. 确认三个实时开关均为默认的 `1`，服务端使用本仓库构建的镜像。
5. 完成自己的小智绑定，确认云端连接能正常建立。

没有执行或无法确认的项目应保留为“未验证”，不能仅因为本项目曾在另一台音箱上运行，就填成通过。

## 真人验收清单

| 操作 | 预期结果 |
| --- | --- |
| 说“你好小智” | 会话就绪后有开始提示音，能够接收第一句话 |
| 连续进行两轮问答 | 不需要每句重新唤醒，第二轮仍可正常接收 |
| 在音箱播报中说话 | 能识别人声，停止当前播报并接收新一句话 |
| 正常听完一条回复 | 末尾不被强制截断，不额外响结束音 |
| 保持安静约 20 秒 | 会话退出，结束提示音只响一次 |
| 退出后再次唤醒 | 能重新进入会话 |
| 容器重启后再试 | 配对身份保留，音箱重连后可用 |
| 音箱整机重启后再试 | 自启生效，owner/client 不重复启动 |
| 网络中断并恢复后再试 | 能恢复连接并重新唤醒，不继续播放旧回复 |
| 持续运行一段时间后再试 | 增强流仍在，能够唤醒和对话 |

对话内容和 PCM 不需要保存到仓库。记录“测试了什么、结果如何、时间与版本”即可。不要为了测试 5 秒恢复而在日常使用设备上随意破坏音频流；该项没有故障注入结果就如实记为未验证。
