# 音频怎样流动

本项目只保留一条底层采音链路。AEC 使用音箱固件现有 VPM，不在 Docker 中另做一套回声消除。

```text
OH2P 麦克风与播放参考
        │
        ▼
单个 arecord → vpm-owner → 固件 libvpm.so
                               │
                      16 kHz 单声道增强 PCM
                               │
                               ▼
                       FVSH1 私有 socket
                               │
                               ▼
                         arecord reader
                               │ 匿名管道
                               ▼
                       open-xiaoai client
                               │ 局域网连接
                               ▼
                    Docker：唤醒 / VAD / 小智协议
                               │
                               ▼
                            小智服务
```

小智返回的语音经 Docker 和音箱客户端播放。实时模式里，这条下行链路不会暂停增强音频上行。

## 音箱端

`vpm-owner` 用绝对路径的 `/usr/bin/arecord` 读取原始输入：48 kHz、4 声道、S32_LE，参考声道索引为 3。VPM 的 type 2 回调输出 16 kHz、单声道、S16_LE 增强音频。

增强音频通过 `/tmp/family-voice-vpm-audio.sock` 提供给 reader。这个名称是兼容接口的一部分，不表示需要安装其他家庭语音项目。订阅协议为 FVSH1；reader 在收到订阅确认后清除初始超时，随后持续读取有界音频包。

只有客户端使用专用 `PATH` 中的 reader。owner 使用绝对路径采音，所以 reader 不会意外递归启动自己，也不会增加第二路底层录音。不把原始音频或增强 PCM 写入文件，不在增强流失败时降级到原始麦克风。

启动参数中的 `--wake-mode sherpa` 用来选择已有的持续增强模式；它不表示音箱端运行了另一套 Sherpa 唤醒模型。公开接入的唤醒识别仍在 Docker 服务中完成。

## 实时会话与插话

只有 `OH2P_REALTIME`、`OH2P_AEC_READY`、`OH2P_CANCEL_READY` 都为 `1` 时才启用实时接线。缺少支持播放取消的扩展时会报错，不应绕过门禁。

唤醒后发送 realtime 监听请求。TTS 开始和结束不会重发监听或停止采音。现有 Silero VAD 对共享增强输入检测到持续约 250 毫秒的语音时，先停止音箱播放，再请求小智取消当前回复；上行保持工作。阈值使用 0.5，短噪声和实际人声的区分效果仍依赖现场 AEC 信号。

正常 TTS 结束允许已经排队的声音播完。新回复、退出或重新唤醒时清除旧播放，新回复重置 Opus 解码器。音频队列有容量上限，控制操作不等待卡住的音频发送；取消失败会关闭当前采集上行，避免把失败状态继续当成正常实时会话。

协议中的 `session_id` 可以区分连接，但同一连接内没有逐回复 turn ID，不能据此保证过滤所有迟到的旧响应。

## 提示音与自动退出

会话准备好后请求音箱播放 `multirounds_tone.opus`；实际退出会话时播放一次 `voip_off.opus`。资源来自设备固件的 `/usr/share/common_sound/`。普通 TTS 结束和插话不播放结束提示音，初始化和清理也不额外响铃。提示音调用有超时，失败不会阻止继续对话或重新唤醒。

当前实时适配的静默退出时间为 20 秒；检测到语音活动会续期，播报期间不按静默退出。修改普通配置中的唤醒超时，不应直接视为已经修改了实时适配器的超时。

## 5 秒增强断流恢复

检测条件是：持续增强模式正在使用、没有显式 capture 请求、原始帧仍在到达、有效增强回调连续 5 秒没有增加。满足条件时调用已有的 `vpm_set_status(2)`，无恢复时至少间隔 30 秒再试。

正常静音仍有 PCM 回调，所以检测不依赖音量大小。它不定时重启服务，也不新建采音进程。该措施已能恢复遇到的增强流停止故障，但不能证明已经找到 VPM 内部停止输出的根因。
